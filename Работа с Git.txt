git reset --soft HEAD~2 - удалить 2 последних комита из лога и вернуться на комит 1 (если их было 3), но содержимое файла останется как в коммите 3. Как будто файл с содержимым коммита 3 является началом работы и самым первым коммитом

5 делаешь пуш на гитхаб, но так как там твоей ветки не существует, то используешь следующую команду для удаленного создания ветки и пуша:
    git push --set-upstreem origin название_своей_ветки
6 идешь на гитхаб и просишь сделать merge своей ветки с master с помощью кнопки COMPARE & PULL REQUEST. Оставляем описание и нажимаем CREATE PULL REQUEST
7 если все принято и смерджино, то удалить свою ветку локально
    git checkout main - сначала нужно уйти с этой ветки в другую
    git branch -d имя_ветки - теперь можно удалить
8 git push origin --delete название_своей_ветки - удалить ветку удаленно в репе (если ее не удалили там)
Обратите внимание, что данного коммита нет сейчас в ветке main на локальном компе и чтобы получить актуальную версию репы надо сделать git pull

                Начало работы с гитом

1) Создаем репозиторий на гитхаб, не добавляем readme.md. В данный момент репозиторий создан, но в нем нет никаких веток. Чтобы ветки появились нужно запушить туда что-нибудь, например .gitignore
2) Содаем новый проект в IDEA, смотрим местоположение чтобы создать в нужном месте диска и нажимаем "Создать" и если стоит галочка Create git repository, то автоматически будет инициализирован локальный гит репозиторий в нашей папке проекта (появится папка .git). Обычно гит сразу автоматически добавляет все файлы, не указанные в .gitignore в индекс. Поэтому надо поправить файл .gitignore внеся в него .idea/ и затем написать 
    git reset 
чтобы удалить все файлы из индекса и нажать обновить и файлы, внесенные в .gitignore исчезнут из менюшки
3) Переименовать master в main (надо быть в ветке master)
    git branch -m main
4) Добавить .gitignore и по желанию другие файлы в индекс и нажать коммит, далее нажать "Push" (cкорее всего попросит ввести арес репы в таком формате - https://github.com/01Yura/test.git)  
5) Чтобы отменить случайный локальный коммит
    git reset --soft HEAD~1
6) Создать новую ветку и сразу в нее перейти (должна стоять галочка "Checkout branch")
7) Сделать изменения, закоммитить и запушить. Зайти на гитхаб и создать "Pull request", описав что было сделано.
8) Если пулл реквест подтвержден, и ветка больше не нужна локально и в репе, то можно удалить их командами:
    git branch -d (-D) имя_ветки
    git push origin --delete имя_ветки
9) Иногда бывает ситуация, что забыл подтянуть изменения из main в свою ветку и чтобы подтянуть, надо сначала перейти в main, спуллить все актуальные изменения из remote репы, затем перейти на свою ветку и выбрать Merge 'main' into наша_ветка или 
    git merge main
10) Чтобы посмотерть отличается ли наша ветка от main надо вести 
    git diff main
11) Если случайно запушил со своей ветки в main, но еще не создал пулл реквест, то можно откатить обратно всё:
    git reset --soft HEAD~1                     - откатываем коммит локально
    git push origin --delete название_ветки     - удаляем ветку удаленно
12) Amend нужен просто если ты сделал комит, но хочешь добавить туда еще файл или изменить сообщение коммита

или

1) Создаем проект, добавляя что не нужно в .gitignore (.idea/) и коммитим
- если какие то файлы после дбавления в .gitignore все равно видны, то в консоле пишем git reset и обновляем. Они исчезнут
2) Нажимаем в меню Git - github - share project on GitHub
3) После 2го шага проект запушится в main




🔁 Пошагово — как правильно обновить homework/junior-level-tests, когда main стал новым источником истины:
✅ Шаг 1. Обнови локальную main из удалённой origin/main
bash
Копировать
Редактировать
git checkout main
git fetch origin
git reset --hard origin/main
Это гарантирует, что твоя локальная main теперь = удалённой main.

✅ Шаг 2. Переключись в homework/junior-level-tests и сделай rebase
bash
Копировать
Редактировать
git checkout homework/junior-level-tests
git rebase main
Теперь все коммиты из junior-level-tests будут "перенесены" как будто бы они сделаны поверх новой main.

🔄 Если возникают конфликты:
Git подскажет тебе, в каких файлах конфликты. Их нужно вручную разрешить, после чего:

bash
Копировать
Редактировать
git add <исправленные файлы>
git rebase --continue
🔄 Альтернатива — merge вместо rebase (если хочется проще, но с более "грязной" историей):
bash
Копировать
Редактировать
git checkout homework/junior-level-tests
git merge main
✨ ИТОГ:
Да, сначала git fetch + reset --hard origin/main на локальной main.

Потом уже от неё делаешь rebase или merge в свою рабочую ветку.
